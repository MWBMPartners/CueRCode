## Cross-cutting findings (from the auditors)

### Batch 1

1) Scheduled/manually-run workflows only work from the default branch (main): .github/workflows/emoji-ingest.yml exists only on alpha/work-in-progress, so the monthly emoji check (#68) is not active until it has been promoted to main. 2) The beta branch has no ci.yml (no test suite, PHP syntax check or gitleaks secret scan on beta), unlike alpha and release-candidate. This affects #64/#103. 3) web/CueRCode.net/_includes/sql/install.sql:1248-1272 uses plain ALTER TABLE ... ADD COLUMN (#70). A second run fails with duplicate column (MySQL 1060) and stops multi_query, so later statements such as tblQRRedirects (line 1315) never run. There is also no upgrade script for databases installed before #70 or E1a. This needs fixing before any real DB test. 4) The 26 predefined-logo PNG copies are still missing (public_html/assets/img/logos has 26 SVG and 0 PNG). On the default PNG output, predefined logos are still dropped unless the host has Imagick (#65, which blocks part of #66). 5) An API request with format='jxl' (or any unknown format) quietly falls back to PNG in fn_api_generate.php:1100-1104 instead of returning an error (#40). 6) SSO (#19/#20) does not sync the avatar or picture, and there is no per-organisation SSO config (waits on #21). 7) Checks run: php tests/run.php gives 2185/2185 passed. php -l on all non-library PHP gives zero errors. actionlint with --severity=error gives rc=0 on the workflows of all four branches (only info-level shellcheck notes appear without that flag). 8) Not possible here: the gh CLI is missing, so the main branch-protection change (#103 2a) cannot be verified. MySQL and bcmath are not available locally. PDF417 numeric mode needs bcmath on Dreamhost. 9) Ready to close: #61 and #67.
